Title

Dynamic Academic Result Card Generator Using React and Google Sheets (Backendless Architecture)

Abstract

This project focuses on the design and implementation of a dynamic academic result card generator using React.js and Google Sheets as a data source, without employing any backend server or database. The system generates visually rich, mobile-optimized result cards by dynamically reading student data from class-wise Google Sheets. Each student’s complete academic data is stored in a single row, while subject structures vary dynamically between classes. All calculations, visualizations, and exports are performed on the client side, resulting in a lightweight, scalable, and cost-effective solution.

1. Introduction

Academic result management systems traditionally rely on backend servers, databases, and complex APIs. While effective, these systems increase development effort, hosting costs, and maintenance overhead. For many educational and content-driven use cases, such complexity is unnecessary.

This project explores a frontend-first approach where structured academic data is maintained in Google Sheets, and the web application dynamically processes and visualizes this data. The system allows result cards to be generated, viewed, and exported as high-quality images suitable for digital sharing.

6. Data Design
6.1 Sheet-to-Class Mapping

Each Google Sheet represents one academic class.
Multiple classes are handled by creating multiple sheets.

Sheet Name	Class
Class_X_A	Class X – A
Class_X_B	Class X – B
Class_IX	Class IX
6.2 Student Data Model (Single Row Design)

Each row in a sheet represents one student.
The first set of columns are fixed identity fields, followed by dynamic subject columns.

Fixed Identity Columns
Column	Description
student_id	Unique student identifier
name	Student name
roll_no	Roll number
session	Academic session

These fields remain consistent across all sheets.

Dynamic Subject Columns

All columns after the identity fields are treated as subjects.
Subject names and count vary between classes.

Example: Class X – Science
student_id	name	roll_no	session	Physics	Chemistry	Biology	Maths
Example: Class VIII – General
student_id	name	roll_no	session	Maths	English	History	Geography	Art

The application dynamically reads column headers to determine subjects.

7. Dynamic Subject Handling

The system does not hardcode subject names.
Instead, it follows this logic:

Read the first row of the sheet (headers)

Ignore fixed identity fields

Treat remaining headers as subjects

Extract marks for the selected student

Generate charts and score indicators dynamically

This enables the system to support unlimited class structures without code modification.

8. Functional Modules
8.1 Data Fetching Module

Fetches class-wise data from Google Sheets

Parses sheet data into JavaScript objects

Handles loading and error states

8.2 Student Selection Module

Filters student rows using student_id or roll_no

Isolates a single student’s academic data

8.3 Calculation Module

Computes total marks

Calculates percentage and averages

Handles missing or empty values gracefully

8.4 Visualization Module

Radar charts for skill or performance metrics

Circular indicators for subject-wise marks

Automatically adapts layout based on subject count

8.5 Export Module

Captures a fixed 9:16 result card layout

Generates high-resolution image output

Optimized for social media sharing

9. Implementation Details

All rendering is data-driven

14. Conclusion

This project demonstrates that a dynamic and visually rich academic result system can be developed using only frontend technologies and cloud-based spreadsheets. By separating data storage from presentation logic and eliminating backend dependencies, the system achieves flexibility, scalability, and simplicity. The project reflects a modern approach to web application design and is suitable for educational visualization use cases.
